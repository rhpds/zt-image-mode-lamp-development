= Module 1: Build and Run LAMP Container

== Introduction

In this module, you'll authenticate to Red Hat Container Registry and build a LAMP (Linux, Apache, MariaDB, PHP) development container. You'll learn how to use **volume mounts** to make your application files available inside the container for fast iterative development.

**What you'll accomplish:**

* Authenticate to Red Hat Container Registry
* Build a container image with the LAMP stack
* Run the container with a volume mount
* Access the container to prepare for application setup

**Time:** Approximately 15 minutes

== Step 1: Authenticate to Red Hat Container Registry

Before you can pull Red Hat base images, you need to authenticate to `registry.redhat.io`.

[source,bash]
----
podman login registry.redhat.io
----

When prompted, enter your Red Hat account credentials:

* **Username:** Your Red Hat account email or username
* **Password:** Your Red Hat account password

**Expected output:**
[source,text]
----
Login Succeeded!
----

[TIP]
====
If you don't have a Red Hat account, create one (free) at https://sso.redhat.com/auth/realms/redhat-external/login-actions/registration
====

== Step 2: Review the Development Environment

Your environment has been pre-configured with a LAMP development directory structure. Let's explore it:

[source,bash]
----
cd ~/lamp-dev/bootc
ls -la
----

You should see:

* `Containerfile` - Container definition for the LAMP stack
* `app/` - Directory for your application files (mounted as a volume)
* Several `.example` files - Templates you can use

**View the Containerfile:**

[source,bash]
----
cat Containerfile
----

This Containerfile:

* Starts from `registry.redhat.io/ubi10/ubi-init` (RHEL Universal Base Image with systemd)
* Installs MariaDB, Apache (httpd), and PHP
* Enables services to start automatically
* Exposes port 80 for web traffic

== Step 3: Build the Development Container Image

Build your LAMP development container image:

[source,bash]
----
podman build -f Containerfile -t lamp-dev-image .
----

**What's happening:**

* Podman pulls the UBI 10 base image from Red Hat's registry
* Installs the LAMP stack packages (MariaDB, Apache, PHP)
* Creates a container image named `lamp-dev-image`

**Expected:** This takes 2-3 minutes. You'll see package installation output.

[NOTE]
====
**Why UBI (Universal Base Image)?**

UBI is Red Hat's freely redistributable base image. It's similar to the RHEL bootc images you'll use in Lab 2, but designed for development containers rather than bootable systems.
====

== Step 4: Run the Container with Volume Mount

Now run the container with a **volume mount** that makes your `app/` directory available inside the container:

[source,bash]
----
podman run -d --name lamp-dev \
  -p 8080:80 \
  -v ~/lamp-dev/bootc/app:/app:z \
  lamp-dev-image
----

**Understanding the command:**

* `-d` - Run in detached (background) mode
* `--name lamp-dev` - Name the container "lamp-dev"
* `-p 8080:80` - Map host port 8080 to container port 80 (Apache)
* `-v ~/lamp-dev/bootc/app:/app:z` - **Volume mount** your app directory
  ** Files in `~/lamp-dev/bootc/app/` on the host appear at `/app/` in the container
  ** `:z` tells SELinux to relabel files so the container can access them
* `lamp-dev-image` - The image you just built

**Verify the container is running:**

[source,bash]
----
podman ps
----

You should see your `lamp-dev` container in the list with status "Up".

[IMPORTANT]
====
**Volume Mounts = Development Workflow**

With volume mounts, you can edit files on the host (where you have your favorite editor) and immediately see changes in the container. This is perfect for development but **not** for production.

In Lab 2, you'll learn the production approach: **copy** files into an immutable bootable image.
====

== Step 5: Access the Container Terminal

You need to configure services inside the container. Access its shell:

[source,bash]
----
podman exec -it lamp-dev /bin/bash
----

You're now **inside the container**. Notice the prompt changes to `[root@<container-id> /]#`.

**Verify you're in the container:**

[source,bash]
----
hostname
----

You should see a container ID (not "buildhost").

**Check that the volume mount is working:**

[source,bash]
----
ls -la /app/
----

You should see the `.example` files from your host's `~/lamp-dev/bootc/app/` directory.

**Exit the container for now:**

[source,bash]
----
exit
----

You're back on the host (prompt shows `[rhel@buildhost]`).

== Understanding Volume Mounts

The volume mount (`-v ~/lamp-dev/bootc/app:/app:z`) creates a **live connection** between:

**Host:** `~/lamp-dev/bootc/app/`
↕
**Container:** `/app/`

Any file you create in either location appears in both. This lets you:

* Edit files on the host with your favorite editor
* See changes immediately inside the container
* Test quickly without rebuilding images

This is the **development workflow**. In Module 2, you'll create application files using this workflow.

== Troubleshooting

**Container won't start:**
[source,bash]
----
podman logs lamp-dev
----

**Check all containers:**
[source,bash]
----
podman ps -a
----

**Remove and restart container:**
[source,bash]
----
podman rm -f lamp-dev
podman run -d --name lamp-dev -p 8080:80 -v ~/lamp-dev/bootc/app:/app:z lamp-dev-image
----
